# FlowPass 補件與正式申請流程設計

## 目標

- 案件進入 `awaiting_documents` 時，申請人可在案件進度頁直接讀取補件要求、上傳指定文件並送出補件。
- 前台不出現「待辦事項」與內部英文狀態。
- 正式方案名稱統一為「軟體補助申請」，不再顯示「示範申請」。
- 草稿不再是使用者功能：不列入申請紀錄、不恢復舊草稿，也不顯示草稿文案；建立新申請時軟刪除同一申請人的舊未送出案件。

## 補件流程

案件詳情在 `awaiting_documents` 狀態讀取該案件的未完成 `provide_document` 任務。公開 API 回傳解密後的申請人可讀說明，但不回傳後台或其他案件資訊。補件介面依後台指定的文件類型映射到既有文件欄位；若後台未指定類型，仍提供「其他補充文件」上傳入口。申請人至少完成一次符合本次要求的上傳後，才能按下「送出補件」，完成任務並將案件轉為 `resubmitted`。

## 草稿邊界

資料庫的 `draft` 仍作為正式送出前的內部狀態，因為答案、附件與 AI 產生流程都需要案件識別碼；它不再出現在申請紀錄或文字介面。每次從正式申請入口開始時建立新案件，並在同一交易中軟刪除先前未送出的案件，避免累積或恢復舊草稿。

## 驗證

不採測試驅動開發。完成實作後執行相關既有測試、完整測試、型別／建置檢查，再重新封裝與部署，最後確認本機與公開健康檢查及頁面資源版本。
