## 1. 目標

在把目前這批未提交變更收成一個版本之前，確認三件事：

1. **9/13 企劃的 10 項修正**真的有照規格運作，不只是單元測試通過。
2. **這一輪新增的功能**（工具檢測、安全圖卡、LINE 聊天回覆、匯率合理性、AI 用量監控等）至少走過一次主流程和主要錯誤情境。
3. **原本就能用的主流程**（申請 → 送件 → 審核 → 撥款 → 結案）沒有被改壞。

## 3. 測試範圍

## 4. 測試環境與資料

| 環境 | 用途 | 規則 |
|---|---|---|
| **T1 本機測試環境** | 自動化、整合、瀏覽器手機模擬 | 資料目錄用 `./.flowpass-test`，**不碰** `~/Library/Application Support/FlowPass`；LINE 和模型可以用假的 |
| **T2 真機環境** | 真實 LINE、LIFF、推播、真 Gemini | 用測試 LINE 帳號；附件只用範例圖片；**需要你明確同意才執行** |

測試資料：
- 用 `scripts/seed-demo.ts` 建立測試方案，申請期間和購買期間要包含今天。
- 準備範例附件：身分證正反面、購買證明、存摺封面、切結書、代付切結書。都用假資料圖片，包含 JPG、HEIC、PDF、超過大小限制的檔案各一份。

- 準備工具名稱：一個在允許清單內、一個用別名、一個被封鎖、一個不存在的名稱。

## 6. 測試案例：9/13 企劃 10 項修正

優先級：**P0** = 會送錯件或誤判，必須通過；**P1** = 體驗問題，可以帶已知問題上線但要記錄。

### 6.1 開始審核（P1）
| 編號 | 步驟 | 預期 |
|---|---|---|
| R1-1 | 後台打開「已送出」案件，按開始審核 | 沒有原因欄位，直接進入審核中 |
| R1-2 | 對「重新送件」案件開始審核 | 同上 |
| R1-3 | 申請端查看時間軸 | 只顯示「開始審查」類的固定摘要，沒有奇怪的原因 |
| R1-4 | 直接呼叫審核 API，不帶原因（補測試） | 決定並記錄預期行為：自動補上，或回傳明確錯誤 |

### 6.2 Injection 失敗體驗（P0）
| 編號 | 步驟 | 預期 |
|---|---|---|
| R2-1 | 四題中任一題貼入 injection 字串，按產生草稿 | 顯示「內容包含系統指令，請僅填寫實際流程。」 |
| R2-2 | 失敗後**不修改**答案，觀察產生按鈕 | 按鈕不能按，或明確要求先修改（⚠️ 目前程式碼可能不符合） |
| R2-3 | 失敗後嘗試進入附件步驟或護照頁 | 進不去 |
| R2-4 | 失敗期間 | 不出現空白護照、空流程圖、「整理完成」 |
| R2-5 | 修改成正常描述後重新產生 | 成功產生草稿 |
| R2-6 | 在追問回答裡貼入 injection（`passport-review-panel`） | 同樣被擋下並停在可以修改的狀態 |
| R2-7 | 字串集逐一測試（補測試） | 全部回 `AI_INPUT_UNSAFE`；正常描述不會被誤判 |

### 6.3 狀態不重疊（P1）
| 編號 | 步驟 | 預期 |
|---|---|---|
| R3-1 | 最後一題打完字立刻按產生 | 畫面同時只有一組主要狀態 |
| R3-2 | 模擬慢網路再按產生 | 儲存狀態結束後才出現產生狀態，兩者不會並列 |
| R3-3 | 產生失敗後再修改答案 | 恢復顯示一般的儲存狀態 |

### 6.4 購買資料（P0）
| 編號 | 步驟 | 預期 |
|---|---|---|
| R4-1 | 不填訂閱起訖日就送件 | 被擋下，錯誤標在欄位旁 |
| R4-2 | 結束日早於開始日 | 顯示欄位錯誤 |
| R4-3 | 開始日等於結束日 | 可以儲存 |
| R4-4 | 後台審核畫面、補助試算 | 看得到訂閱區間 |
| R5-1 | 首次申請，末四碼和持卡人姓名都空白 | 被擋下 |
| R5-2 | 只填末四碼、不填姓名（反過來也測） | 被擋下 |
| R5-3 | 末四碼輸入字母或 3 位數 | 無法輸入或顯示錯誤 |
| R5-4 | 已登記付款指紋的案件，兩欄留空 | 可以儲存，並顯示「沿用既有登記」 |
| R5-5 | 查詢資料庫（補測試） | 找不到末四碼和持卡人姓名的明文 |
| R6-1 | 幣別選新臺幣，原始費用填 1990 | 不顯示換算欄位，自動帶入 NT$1,990 |
| R6-2 | 新臺幣填 1990.5 | 依整數規則處理，並在文件記錄規則 |
| R6-3 | 從美元切回新臺幣 | 之前填的換算金額被正確覆蓋 |
| R6-4 | 美元填 29.99，換算金額填明顯不合理的數字 | 能儲存，但勾稽出現匯率合理性紅燈 |
| R6-5 | 幣別選「其他」 | 需填幣別名稱；勾稽顯示「待人工確認換算」 |
| R7-1 | 不填申請人姓名就送件 | 被擋下 |
| R7-2 | 後台案件列表、詳情 | 顯示填寫的姓名，不是 LINE 顯示名稱 |

### 6.5 附件規則（P0）
| 編號 | 付款人 | 上傳的切結書 | 預期 |
|---|---|---|---|
| R8-1 | 本人 | 都沒有 | 不能送件 |
| R8-2 | 本人 | 只有切結書 | 可以送件 |
| R8-3 | 代付 | 只有切結書 | 不能送件 |
| R8-4 | 代付 | 只有代付切結書 | 不能送件 |
| R8-5 | 代付 | 兩份都有 | 可以送件 |
| R8-6 | 代付改回本人 | 已上傳的代付切結書 | 不再是必填，也不擋送件 |

### 6.6 資安三層語意（P0）
| 編號 | 步驟 | 預期 |
|---|---|---|
| R10-1 | 後台建立事件，工具選 ChatGPT，預覽出候選案件，**不發布** | 申請端沒有專屬提醒；總結卡不能寫「完全沒有事件」 |
| R10-2 | 發布事件並確認 1 個案件受影響 | 該申請人總結卡顯示「有 1 則專屬提醒需要你處理」，LINE 收到資安提醒 |
| R10-3 | 另一個也用 ChatGPT、但沒被確認的申請人 | 看到「公開事件中有 N 則與你的護照相關」，沒有專屬提醒 |
| R10-4 | 沒有使用相關工具的申請人 | 看到公開事件列表，總結不暗示與他有關 |
| R10-5 | 事件填受影響版本，申請工具版本不在清單 | 不列入預覽 |
| R10-6 | 事件填時間區間，使用時點在區間外 | 不列入預覽 |
| R10-7 | 申請人把提醒標為已讀、承辦標為已解決 | 兩邊狀態一致，數字對得上 |
| R9-1 | 請一位不熟系統的人看後台發布頁 | 能說出為什麼列為候選、申請人何時才看得到（P1） |

## 7. 測試案例：新功能與主流程回歸

### 7.1 主流程回歸（P0）
| 編號 | 流程 | 預期 |
|---|---|---|
| F-1 | 四題 → 產生草稿 → 回答追問 → 確認護照 → 購買資料 → 附件 → 送件 | 每步成功；LINE（或假的 LINE）收到「申請已送出」 |
| F-2 | 開始審核 → 核准（在上限內）→ 列入撥款 → 已撥款 → 結案 | 狀態、時間軸、通知、金額都正確 |
| F-3 | 核准金額超過上限、沒填 override 原因 | 被擋下 |
| F-4 | 審核中 → 要求補件 → 申請人補件 → 重新送件 → 再次審核 | 補件內容後台看得到 |
| F-5 | 審核中 → 退回修正（要求重新確認護照）→ 申請人修改並確認 | 產生新護照版本，舊版本不變 |
| F-6 | 駁回 | 之後任何操作都被拒絕 |
| F-7 | 用 A 帳號存取 B 的 caseId、附件下載、job 狀態 | 一律拒絕，也不透露資料是否存在 |

### 7.2 新功能（P1，標示者為 P0）
| 編號 | 功能 | 案例 | 預期 |
|---|---|---|---|
| N-1 | 工具檢測頁 | 未確認護照、已確認護照、沒有工具三種狀態 | 總結卡文字依第 6.6 節規則顯示 |
| N-2 | 公開工具狀態頁 | 未登入直接開啟 | 只顯示公開事件，沒有任何個人資料（**P0**） |
| N-3 | 安全圖卡 | 產生並下載圖片 | 圖片正常；LIFF 裡下載失敗時提示長按儲存；圖卡不含敏感護照細節（**P0**） |
| N-4 | 允許工具清單 | 搜尋、別名、封鎖名稱、選「其他」 | 封鎖名稱無法選；別名對應到正確工具 |
| N-5 | 追問選項安全提示 | 選到有風險的選項 | 顯示對應提示，不阻擋作答 |
| N-6 | 送件勾稽 | 兩個案件用同一張發票號碼 | 第二件出現重複發票紅燈；後台列表紅燈數量正確 |
| N-7 | LINE 聊天回覆 | 輸入「常見問題」「我的案子到哪了」「為什麼只核 3000」「ChatGPT 安全嗎」、隨便打字 | 各自回覆正確類型；無法辨識時回覆預設訊息 |
| N-8 | AI 用量監控 | 連續觸發產生草稿 | 後台用量數字增加；到達上限時申請端顯示「整理次數已達上限」 |
| N-9 | Gemini 故障 | 模型逾時、回傳壞掉的 JSON、額度用完 | 申請端顯示可重試的錯誤；有設定備援時改用 LM Studio |
| N-10 | 維護模式 | 開啟維護模式 | 公開頁顯示維護中，後台仍可使用 |
| N-11 | 後台時間選擇器 | 設定補件期限、事件時間 | 時區正確，存檔後顯示一致 |

### 7.3 Worker 可靠性（P0）
| 編號 | 案例 | 預期 |
|---|---|---|
| W-1 | 產生草稿途中停止 worker 再啟動 | job 被重新接手完成，不會卡住或跑兩次 |

## 8. 發版演練（P4）

依序執行並保存輸出：

1. `npm run build:release`
2. `npm run package:release`，檢查 manifest 雜湊
3. `npm run backup` → `npm run restore:check`
4. `npm run ops:doctor -- --offline`
5. 回滾演練：切到新版本後回滾到前一版，確認 data、vault、backups 都沒變

證據依 `docs/acceptance-evidence.md` 保存。沒執行的項目不能標成通過。
