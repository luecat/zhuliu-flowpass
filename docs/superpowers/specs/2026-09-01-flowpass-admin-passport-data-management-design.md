# FlowPass 單一護照資料管理設計

狀態：已確認設計，待實作計畫  
日期：2026-09-01

## 目標

新增一套正式環境可使用的後台資料管理功能。管理員可用案件編號找到單一護照，查看該護照與其一對一案件的完整關聯資料，安全地覆寫允許修改的業務欄位，或不可逆地清除該護照的所有相關紀錄、附件與可能保留該資料的 FlowPass 備份。

此功能不是通用資料庫瀏覽器，也不提供任意 SQL。所有讀取、修改與刪除都由伺服器端的 FlowPass 資料關聯規則控制，避免前端傳入資料表名稱、欄位名稱或刪除條件後直接操作資料庫。

## 已確認決策

- 管理介面同時提供「易讀分組檢視」與「進階原始資料檢視」。
- 原始資料檢視為唯讀；修改仍經過同一套安全編輯服務。
- 修改採直接覆寫原紀錄，不另外建立修正版。
- ID、外鍵、擁有者、版本號、雜湊、加密參照、儲存路徑與系統結構欄位不可修改。
- 修改來源欄位後，自動重算可確定重建的索引、規則與補助金額；AI 內容不自動重跑，只標記需要更新。
- 清除範圍只限指定護照及其一對一案件，不刪除申請人，也不影響同一申請人的其他護照。
- 清除是實體且不可逆的完整清除：資料庫關聯紀錄、附件檔案，以及所有可能含有該資料的 FlowPass 管理備份都必須移除。
- 管理員已接受清除舊 FlowPass 備份會同時失去其他案件在那些時間點的復原能力。
- 清除前需完成三階段確認：檢視精確影響範圍、輸入完整案件編號、再次輸入管理員密碼。
- 不採測試驅動開發；完成實作後才執行針對性與完整驗證。

## 範圍與不包含項目

### 本次範圍

- 後台案件列表進入單一護照的「資料管理」頁面。
- 讀取該護照及其案件的完整業務資料與關聯紀錄。
- 依白名單覆寫單一業務欄位。
- 自動維持加密、雜湊、索引與可確定衍生資料的一致性。
- 預覽並完整清除單一護照關聯圖。
- 清除 FlowPass 自己管理的 SQLite 備份與文件庫附件。
- 清除流程的維護模式、失敗復原與完成後驗證。

### 不包含項目

- 任意 SQL、任意資料表修改或通用資料庫管理器。
- 修改全域方案、方案週期、補助規則、工具目錄、管理員帳號或系統秘密。
- 刪除申請人，或依申請人批次刪除多個護照。
- 清除 macOS Time Machine、APFS 快照、雲端磁碟、第三方備份或使用者自行複製的檔案。
- 以此介面替換附件內容；附件重新上傳必須沿用正式補件或文件上傳流程。
- 實作過程自動清除目前正式資料；任何實際清除仍需管理員在新介面逐次確認。

## 使用者介面

### 入口與版面

既有後台案件列表的每一筆案件增加「資料管理」入口，開啟完整頁面而非狹窄側欄。頁面頂部固定顯示案件編號、目前狀態、申請人識別摘要、最後更新時間，以及是否有資料需要重新產生。

左側導覽依業務意義分組：

1. 案件與申請人答案
2. 購買內容與金額
3. 護照與歷次護照版本
4. 文件、欄位辨識與補件
5. 任務、審查與狀態流轉
6. 時間軸與通知
7. 規則判定與補助計算
8. AI、OCR、警示與事件
9. 系統關聯與管理稽核

頁面提供全域搜尋，可依欄位名稱、顯示標籤、紀錄 ID 或文字值定位資料。一般檢視使用中文標籤、格式化日期、金額及狀態；內部英文代碼只在展開的技術資訊或進階檢視出現。

### 易讀分組檢視

每一筆資料顯示來源、更新時間與是否可編輯。可編輯欄位以明確的「編輯」動作進入單欄編輯，不讓整張表格直接進入可輸入狀態。送出前顯示新值與會觸發的重算項目；成功後更新目前頁面，衝突或驗證失敗時保留輸入並提供可理解的錯誤說明。

### 進階原始資料檢視

進階模式依資料表與關聯層級顯示原始欄位名稱、紀錄 ID、資料型別、目前儲存狀態、列版本與關聯來源。它是唯讀檢視，不提供 SQL 輸入框或直接儲存按鈕。

為避免把加密設計本身變成資料外洩面，介面顯示解密後的授權業務值，以及密文長度、摘要與 key ID 等儲存中繼資料；不回傳完整密文、主金鑰、文件庫金鑰、工作階段秘密或密碼雜湊。

### 危險區域

頁面底部固定分隔出「永久清除此護照」危險區域。第一步只產生清除預覽，不立即刪除。預覽需列出：

- 目標案件編號、護照 ID 與申請人摘要
- 每一類資料表的紀錄數與實際紀錄 ID
- 附件檔案數、總容量與受控路徑
- 需要語意比對的工作、稽核與冪等紀錄數
- 將被移除的 FlowPass 備份清單與時間
- 明確保留的同申請人其他案件數量

管理員確認預覽後，必須完整輸入畫面上的案件編號，再輸入目前管理員密碼。兩者皆正確且資料圖未變動，才可取得一次性清除授權並執行。

## 讀取模型

新增專用的 `AdminPassportDataSnapshot` 服務，以案件 ID 為入口建立完整、型別化的關聯快照。每筆紀錄至少包含：

- 邏輯資源名稱與來源資料表
- 紀錄 ID、父層關聯與列版本
- 易讀業務欄位與格式化顯示值
- 原始欄位名稱、資料型別與儲存中繼資料
- 是否可編輯，以及不可編輯的原因
- 是否為來源資料、衍生資料或歷史資料

服務必須以固定查詢取得所有關聯資料，不接受前端指定 JOIN、資料表、欄位或 WHERE 條件。管理員只能在既有 Cloudflare Access、管理員工作階段、Cookie、CSRF 與 no-store 安全邊界內讀取快照。

快照範圍包括案件、答案、購買資料、護照與版本、確認與追問、節點／邊／工具索引、文件及欄位、OCR、任務、狀態流轉、時間軸、通知、規則評估、補助計算、AI 執行、警示、事件比對、發票指紋，以及能以目標 ID 安全歸屬的工作、LINE／webhook 事件、稽核和冪等紀錄。

## 單欄編輯

### 介面契約

編輯端點接受固定格式：

```json
{
  "resource": "purchaseDetails",
  "recordId": "record-id",
  "field": "requestedAmount",
  "value": 200,
  "expectedRowVersion": 4
}
```

伺服器使用內建 registry 將 `resource` 與 `field` 映射到明確的 repository 操作；不得把用戶輸入插入 SQL 識別字。每次寫入都需通過現有管理員驗證、CSRF、冪等控制、型別驗證、欄位規則與 `expectedRowVersion` 樂觀鎖定。

### 可編輯與鎖定範圍

允許修改的項目僅限具明確業務含義且可安全重建相依資料的欄位：

- 申請答案的四個文字答案
- 購買內容、數量、單價、申請金額與業務日期
- 護照 payload schema 內的使用者或審查業務欄位
- 案件允許的業務狀態、核定金額、公開說明與決策日期
- 任務標題、指示、期限與可驗證狀態
- 警示的公開摘要、處理指引、狀態與結案日期
- 時間軸事件的公開摘要與公開資料內容
- 附件顯示檔名

下列項目一律鎖定：所有 ID、外鍵、擁有者、案件編號、版本序號、目前版本指標、事件序號、origin、雜湊、密文、key ID、文件實體路徑、MIME／大小／內容摘要、建立時間、系統更新時間、管理員安全資料、全域方案及規則資料。

規則評估、補助計算、AI/OCR 執行結果、護照索引、文件辨識欄位與事件歷史屬於衍生或歷史資料，不允許直接修改。要改變結果必須修改其允許的來源欄位，再由系統重算。

### 一致性處理

單欄覆寫與其同步相依處理需在單一交易中完成：

1. 驗證列版本與欄位白名單。
2. 對敏感值重新加密，更新內容雜湊與列版本。
3. 重建受影響的護照節點、邊與工具索引。
4. 重跑確定性的規則判定與補助金額計算。
5. 將受影響的 AI 內容標記為「需要更新」，但不自動呼叫模型。
6. 寫入不含舊值或新敏感值的管理稽核紀錄。

管理稽核只保存管理員、資源類型、紀錄 ID、欄位名稱、資料型別、時間、請求 ID 與成功／失敗結果，不保存修改前後的敏感內容。

案件狀態若被直接校正，既有狀態流轉保留為歷史事實，不回寫或偽造過去事件；新的管理稽核紀錄明確表示這次是資料校正。任何已送出的通知不會被撤回。

## 單一護照完整清除

### 關聯圖與預覽

清除服務使用與讀取快照相同的固定 relation registry 建立目標關聯圖，涵蓋所有直接外鍵、間接外鍵、JSON payload 內的案件／文件參照，以及以 `entity_type`、`entity_id`、LINE／webhook payload 或冪等 scope 歸屬目標案件的紀錄。

預覽回傳精確 ID、分類數量、附件清單、備份清單與一個綁定下列內容的簽章摘要：

- 目標案件與護照
- 完整關聯圖及列版本
- 目前資料庫版本
- 附件檔案摘要
- 預計移除的 FlowPass 備份集合

若任何相關資料、附件或備份集合在確認期間改變，預覽立即失效，管理員必須重新檢視。

### 一次性授權

完整案件編號與管理員密碼驗證成功後，伺服器簽發只綁定該目標及預覽摘要的一次性清除權杖。權杖只保存雜湊、五分鐘失效、使用一次即作廢，也會在關聯圖改變時失效。遠端操作仍需通過 Cloudflare Access，所有操作沿用現有管理員工作階段與 CSRF 防護。

### 執行順序

清除協調器依下列階段執行：

1. 取得全域資料維護鎖，暫停公開寫入、後台寫入與 worker 寫入，但保留健康檢查與維護狀態查詢。
2. 建立並驗證一份暫時的清除前復原備份。
3. 依預覽中的精確受控路徑，把目標附件移入隔離區；禁止以未驗證 glob 或寬泛目錄作為刪除目標。
4. 開啟 SQLite `BEGIN IMMEDIATE` 交易，按固定依賴順序刪除目標關聯圖。
5. 先刪文件欄位審查、欄位、OCR 原始資料與執行、發票指紋等文件子紀錄。
6. 刪除護照確認、追問與回答、節點／邊／工具索引等護照版本子紀錄。
7. 刪除通知、任務、警示、事件比對、補助計算、規則評估、AI 執行、時間軸與狀態流轉。
8. 依精確關聯圖清除 JSON 工作、LINE／webhook 事件、稽核 entity、API 冪等與其他無外鍵但可安全歸屬的紀錄。
9. 刪除購買資料、答案版本、護照版本、護照、文件與案件本體。
10. 在交易內驗證所有目標 ID 已不存在、沒有目標孤兒紀錄，且同申請人的其他護照與全域資料筆數及摘要不變。
11. 提交交易，建立並驗證一份不含目標資料的新正式 FlowPass 備份。
12. 實體刪除隔離附件、暫時復原備份，以及所有可能含有目標資料的舊 FlowPass 管理備份。
13. 再次掃描現行資料庫、文件庫與 FlowPass 備份目錄，確認沒有目標案件編號、目標 ID 或目標附件摘要。
14. 解除維護鎖，回傳完成結果。

清除不刪除 applicants、applicant_sessions、LINE 身分、全域方案／週期／規則、工具目錄、全域安全事件或同一申請人的其他案件。若某筆無外鍵紀錄無法被證明只屬於目標護照，清除必須停止並回報，而不是猜測或擴大刪除。

完成後不保留任何含目標案件編號、目標 ID 或目標內容的清除收據。系統可以只增加不含目標或操作者識別資訊的匿名整體成功／失敗計數；操作中的可識別日誌必須在最終清除階段一併移除。

### 失敗與復原

- 在資料庫提交前失敗：回滾交易、將附件從隔離區復原，驗證資料一致後解除維護鎖。
- 在資料庫提交後、舊備份清除前失敗：保持維護模式，移除過程中產生的清除後備份，使用暫時復原備份與附件隔離區還原到清除前狀態，再驗證後解除維護鎖。
- 在新正式備份驗證後、最終實體清除期間失敗：保持維護模式，不接受新寫入；以相同預覽與已消耗授權的內部恢復狀態重試剩餘清理，不能要求前端重新發出不完整的刪除。
- 只有在資料庫、文件庫與 FlowPass 備份三者都通過無殘留檢查後，介面才顯示完成。

## 安全模型

- 不新增任意 SQL、資料表名稱、欄位名稱、檔案路徑或 shell 指令入口。
- 所有編輯與清除使用明確 allowlist 與 relation registry。
- 每次寫入驗證管理員工作階段、Cloudflare Access 身分、CSRF、來源、內容型別與請求大小。
- 密碼只用於即時驗證，不寫入清除權杖、稽核或應用程式日誌。
- 清除權杖綁定管理員、目標、預覽摘要、到期時間與單次使用狀態。
- 所有欄位值進入日誌前經過敏感資料遮罩；完整 payload、密文與附件內容不進入日誌。
- 進階原始檢視與一般檢視使用相同的授權查詢，不因「原始」模式放寬資料邊界。
- 維護鎖必須由 public、admin、worker 三個 runtime 共同遵守，不能只在前端停用按鈕。

## 程式結構

既有 `server/admin/app.ts` 只負責掛載新路由與共同安全中介層；資料管理實作拆分為：

- `server/admin/routes/data-management.ts`：HTTP 契約、驗證與錯誤映射
- `server/services/admin-passport-data-service.ts`：完整快照與原始檢視
- `server/services/admin-passport-edit-service.ts`：欄位白名單、覆寫與相依重算
- `server/services/admin-passport-purge-service.ts`：預覽、授權、維護鎖、清除與復原
- `server/db/admin-passport-relation-registry.ts`：唯一的關聯圖與刪除順序定義
- `admin/data-manager.tsx` 與專用樣式：完整資料管理頁面

若需要新增資料表，migration 只建立欄位編輯稽核、一次性清除授權與全域維護鎖所需的最小結構。資料管理頁不得把更多功能繼續堆進現有大型 `admin/main.tsx`。

## HTTP 介面

- `GET /admin/v1/data/passports/:caseId`：取得易讀與進階快照。
- `PATCH /admin/v1/data/passports/:caseId/fields`：覆寫一個白名單業務欄位。
- `POST /admin/v1/data/passports/:caseId/reconcile-ai`：由管理員明確觸發需要更新的 AI 工作；此端點不由欄位編輯自動呼叫。
- `POST /admin/v1/data/passports/:caseId/purge-preview`：建立精確清除預覽與簽章摘要。
- `POST /admin/v1/data/passports/:caseId/purge-authorizations`：驗證案件編號與管理員密碼，簽發一次性權杖。
- `POST /admin/v1/data/passports/:caseId/purge`：消耗一次性權杖並執行完整清除。
- `GET /admin/v1/data/maintenance-status`：只回傳維護階段與是否可寫，不回傳目標敏感資料。

所有錯誤以穩定代碼區分權限不足、列版本衝突、資料驗證失敗、預覽過期、關聯不明、維護中、復原中與清除失敗。介面提供可處理的中文訊息，不顯示 SQL、檔案系統路徑或堆疊資訊。

## 驗證策略

不採 TDD。功能完成後依下列順序驗證：

1. 讀取快照：授權邊界、完整關聯、解密顯示、秘密遮罩與 raw 唯讀限制。
2. 單欄編輯：每個白名單型別、禁改欄位、重新加密、雜湊／索引重建、規則與金額重算、AI 更新標記。
3. 寫入競爭：列版本衝突、冪等重送、工作階段／CSRF／Access 失效。
4. 完整清除 fixture：每一種直接與間接關聯都被移除，沒有孤兒資料。
5. 隔離保護：同一申請人的其他護照、其他申請人、全域方案與安全資料完全不變。
6. 實體檔案：目標附件被移除，非目標附件保留。
7. 備份：舊 FlowPass 備份被移除，新備份可還原且不含目標資料。
8. 故障注入：在每個清除階段中斷，確認回滾、恢復或維護模式行為符合設計。
9. UI：手機與桌面版分組、搜尋、單欄編輯、衝突提示、三階段確認及鍵盤操作。
10. 完整 typecheck、lint、測試、正式建置與本機／公開健康檢查。

## 發布順序

1. 在 migration 前建立並驗證正式資料備份。
2. 部署 migration、伺服器服務與後台 UI。
3. 只在正式資料上執行清除預覽，確認各資料類別與附件／備份數量，不執行清除。
4. 以一筆可控制的測試護照完成讀取、欄位覆寫與相依重算驗證。
5. 由管理員自行選定目標並完成三階段確認後，才允許第一次正式清除。

## 驗收條件

- 管理員可從案件列表進入完整資料管理頁，讀到指定護照及案件的所有授權業務資料。
- 一般檢視不暴露內部英文狀態，進階檢視可追查來源但不暴露秘密或提供直接寫入。
- 每個可編輯欄位都有明確型別、驗證、列版本與相依重算；所有結構欄位均無法修改。
- 修改不產生新修正版，且稽核不保存修改前後的敏感值。
- 清除前能精確預覽所有資料、附件與 FlowPass 備份影響範圍。
- 未輸入完整案件編號、未通過管理員密碼或預覽已過期時，清除無法執行。
- 清除完成後，現行資料庫、文件庫及 FlowPass 管理備份均找不到目標案件、護照、相關 ID 或附件摘要。
- 同一申請人的其他護照與所有非目標資料保持不變。
- 任一清除階段失敗時，不會在解除維護鎖後留下半套資料。
