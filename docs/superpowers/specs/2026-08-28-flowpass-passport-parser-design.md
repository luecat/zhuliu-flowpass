# FlowPass 同頁護照解析器設計

日期：2026-08-28

## 目標

在既有 FlowPass 提示詞產生器中加入第二個工作模式，讓使用者把 AI 回傳的 `passport_draft` JSON 貼回同一頁，並在瀏覽器內完成格式驗證、資料流檢查與人類可讀的護照呈現。

這是黑客松測試介面，不是正式上線產品。它不連接 AI API、不建立帳號、不儲存資料，也不將貼上的內容送出瀏覽器。

## 使用流程

1. 使用者在「產生提示詞」模式回答四個問題並複製提示詞 JSON。
2. 使用者將提示詞交給任一支援 JSON 的 AI 工具。
3. 使用者切換至同頁的「解析護照」模式，貼上 AI 回傳內容。
4. 使用者按下「解析護照」。
5. 頁面顯示語法、格式契約與節點引用檢查結果。
6. 格式可讀時，頁面同時顯示案例摘要、資料流、安全措施、待確認問題與未知欄位。

解析模式預載本次黑客松的「社團招生影片製作與發布」範例，讓展示者可立即操作；使用者可清除後貼上其他回傳結果。

## 介面架構

頁面保留目前 Figma 風格與三欄骨架，在主畫布上方加入主要工作模式切換：

- `產生提示詞`：完整保留現有四欄輸入、情境範例、JSON 產生與複製功能。
- `解析護照`：切換為解析器專用內容，但保留兩個模式各自尚未送出的內容。

解析模式的三欄職責：

- 左欄：顯示四層檢查狀態，包括 JSON 格式、FlowPass 契約、節點連線、待確認事項。
- 中欄：提供可見標籤的大型 JSON 輸入框、載入範例、清除與解析按鈕；解析後在下方顯示案例摘要與可閱讀的資料流連線卡片。
- 右欄：顯示「AI 草稿，尚未確認」狀態、數量摘要、安全措施、依優先順序排列的確認問題、未知欄位與承辦提示。

資料流以 CSS 卡片和完整文字連線呈現，例如「社員照片 → AI 影片生成工具：提供照片素材供 AI 生成影片」。本次不做 SVG 線路、自由拖曳或自動排版圖形，避免分支與手機版產生難以閱讀的畫面。

## 程式邊界

新增純函式解析模組 `app/passport-parser.ts`，負責：

- 將使用者文字轉為 JSON。
- 檢查 FlowPass 護照格式。
- 檢查所有節點 ID 與引用關係。
- 建立頁面所需的統計摘要與可讀連線。

頁面元件只負責保存兩種工作模式的狀態、觸發解析與呈現結果，不在元件內重複驗證規則。

既有 `PASSPORT_JSON_SCHEMA` 改為可由產生器和解析器共同使用的匯出值，避免兩套格式隨修改而分歧。解析器的公開結果介面為：

```ts
type FlowPassParseResult = {
  status: 'invalid_json' | 'invalid_contract' | 'valid_with_warnings' | 'valid';
  passport: PassportDraft | null;
  issues: ValidationIssue[];
  summary: PassportSummary | null;
};
```

所有狀態都代表解析品質，不代表補助核准、資料安全或法律合規。

## 驗證規則

### 1. JSON 格式

- 空白輸入與無法解析的 JSON 為錯誤。
- 若去除前後空白後，整段內容恰好由一組 Markdown `json` code fence 包住，可移除 fence 後解析，但須顯示「回傳內容不是純 JSON」警告。
- 不從任意說明文字中猜測或擷取 JSON，以免解析錯誤內容。

### 2. FlowPass 契約

- 使用 Ajv 2020 驗證與提示詞產生器相同的 Draft 2020-12 Schema。
- 檢查 `passport_draft` 及其必要區段、欄位型別、列舉值、固定值與額外欄位。
- 錯誤須包含可定位的 JSON path，不能只顯示「解析失敗」。
- 契約錯誤時只顯示問題清單，不建立護照視圖；修正並重新解析後才呈現摘要。

### 3. 圖譜完整性

- 節點、連線、安全措施與確認問題的 ID 不可為空或在各自集合內重複。
- 每條 edge 的 `from_node_id` 與 `to_node_id` 必須指向存在的節點。
- safety action 與 confirmation question 的節點引用必須存在。
- self-loop 與不存在的引用為錯誤；重複連線與 cycle 為警告。
- 沒有任何連線的 data、ai_tool、plugin、storage、destination 節點為警告；person 與 organization 孤立為提示。
- `retention.storage_location` 若等於既有節點 ID 或以 `node_` 開頭，必須指向存在的 storage 節點。
- 公開分享時若沒有至少參與一條 edge 的 destination 節點，顯示警告。

### 4. 待確認狀態

以下內容是待辦或提醒，不是 Schema 錯誤：

- `needs_confirmation` 為 true 的節點、連線、分享與保存資訊。
- `audit.unknown_fields` 中列出的未知欄位。
- 高、中、低優先度的確認問題。
- 高敏感資料、公開分享、未知保存期限、未知工具與承辦審查。

介面不合成風險分數，也不把「沒有錯誤」寫成「安全」或「已核准」。

## 解析結果

成功讀取後至少顯示：

- 案例標題、用途與預期成果。
- 節點、連線、安全措施、確認問題數量。
- 節點敏感程度分布。
- 高、中、低優先問題數量。
- 分享範圍與保存位置、期限、刪除計畫。
- 指定工具與是否需要承辦審查。
- 每條可讀資料流連線。
- 孤立節點、無效引用與其他檢查問題。
- 安全措施及其原因與證據類型。
- 未知欄位清單。

內建範例的預期摘要為 8 個節點、4 條連線、4 項安全措施、8 個確認問題；優先度為高 3、中 4、低 1。引用皆存在，但兩個個資節點及一個組織節點沒有連線，應顯示警告或提示。保存期限、刪除計畫與指定工具為未知。

## 錯誤處理與安全

- 原始輸入即使解析失敗也保留，方便使用者修正。
- 錯誤顯示使用 `role="alert"`，成功或警告摘要使用 `aria-live="polite"`。
- 使用者輸入只以 React 文字節點呈現；HTML 或 script 字串不得當作標記執行。
- JSON 輸入框關閉拼字檢查並提供清楚提示，不要求貼入照片、錄音或文件原文。
- 不使用 `fetch`、localStorage、Cookie 或任何後端儲存。

## 響應式與無障礙

- 桌面維持三欄；較窄筆電將右欄移至下方；手機為單欄。
- 主要模式切換與解析按鈕至少 44px 高，支援鍵盤與觸控。
- 高、中、低與錯誤、警告狀態必須有文字，不只依賴顏色。
- 每條連線提供完整文字，箭頭只作為視覺輔助。
- 切換模式後保留產生器與解析器各自的草稿。

## 測試與驗收

新增純函式測試：

- 內建範例產生正確摘要。
- 無效 JSON、空白輸入與 fenced JSON。
- 缺少必要欄位與錯誤列舉值包含可讀 path。
- 重複 ID、dangling reference、self-loop、孤立節點與 unknown fields。
- 高、中、低問題分組正確。

新增頁面互動測試：

- 兩種主要模式可切換，且各自草稿不遺失。
- 內建範例顯示 8／4／4／8 摘要。
- 無效 JSON 顯示 alert 且保留輸入。
- 契約錯誤顯示具體 JSON path。
- HTML 與 script 字串只顯示為文字。
- 原有產生、過期複製防護與剪貼簿測試全部繼續通過。

完成標準：所有既有與新增測試通過、靜態檢查通過、正式建置成功，並更新到既有公開測試網址。

## 非目標

- 不直接呼叫 AI 或管理 API 金鑰。
- 不提供登入、案件儲存、多人協作或正式承辦決策。
- 不驗證工具服務條款、發票真偽或法律合規。
- 不自動修正 AI 回傳的語意內容。
- 不提供通用 JSON 編輯器、檔案上傳或拖曳式圖譜。
